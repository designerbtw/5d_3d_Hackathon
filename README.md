# AI-ассистент печати для STE Slicer

Плагин для STE Slicer (форк Cura 3.6, Stereotech). В слайсере появляется чат: пользователь описывает задачу текстом и прикладывает STL/OBJ/3MF или фото, а LLM через инструменты выбирает режим печати (3D / 5D Spiral / 5D), материал, профиль и настройки, ориентирует и расставляет модель, запускает слайсинг, сохраняет проект 3MF и G-code и объясняет свои решения.

> Пример: «Кронштейн под нагрузку, PETG, без поддержек» + STL → настроенный проект, G-code и объяснение выбранных параметров.

## Установка

1. В STE Slicer: Справка → Показать папку конфигурации.
2. Скопируйте папку `AIAssistant/` в `plugins/` внутри папки конфигурации (`%APPDATA%\steslicer\7.x\plugins`).
3. Перезапустите слайсер.
4. Меню Расширения → AI Assistant → Open chat. Откроется браузер с чатом.
5. В чате: Настройки → введите API-ключ, при необходимости Base URL и модель → «Проверить соединение».

Значения по умолчанию: `https://api.timeweb.ai/v1`, модель `dashscope/qwen3.8-flash`. Ключ хранится в настройках приложения, в коде его нет. Переменные окружения `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` имеют приоритет.

Код совместим с Python 3.5 (без f-строк и новых модулей), внешних зависимостей кроме `numpy` из дистрибутива нет.

## Запуск без слайсера (для разработки)

```
set LLM_API_KEY=ваш_ключ        # PowerShell: $env:LLM_API_KEY="..."
python dev.py
```

Поднимается тот же чат, а вместо слайсера работает `FakeSlicer`: можно отлаживать промпты, интерфейс и логику агента.

## Как это устроено

```
Браузер (SPA) ── fetch / SSE ──► локальный сервер 127.0.0.1 (случайный порт, токен)
                                   ├─ Агент: цикл диалога с LLM (OpenAI-совместимый API)
                                   ├─ /mcp: тот же реестр как MCP-сервер (JSON-RPC 2.0)
                                   └─ Реестр инструментов ──run_on_main──► API слайсера
```

Ключевая идея: **код считает, модель выбирает**.
- Геометрию (габариты, свесы, варианты ориентации) считает код, модель выбирает из таблицы вариантов.
- Каждое значение настройки проходит белый список с диапазонами; в ответе инструмента видно, что реально применилось и что отклонено.
- Типовые рецепты материалов лежат в базе знаний; если в рецепте `null`, агенту запрещено придумывать число.
- Если модель забыла сохранить результат после слайсинга, плагин делает экспорт сам.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Инструменты (MCP)

| Группа | Инструменты |
|---|---|
| Состояние и режим | `get_state`, `set_print_mode` (classic / cylindrical / cylindrical_full) |
| Материал и профили | `set_material`, `set_quality`, `get_material_recipe` |
| Настройки | `search_settings`, `set_settings` |
| Модели | `load_model`, `list_objects`, `transform_model`, `delete_model`, `arrange_all` |
| Ориентация | `analyze_orientation`, `apply_orientation` |
| Слайсинг и результат | `slice`, `export_gcode`, `save_project_3mf` |

MCP-эндпоинт: `POST /mcp` с заголовком `X-Token` (токен печатается в адресе чата).

## Безопасность

- Сервер слушает только `127.0.0.1`, проверяется заголовок `Host` (защита от DNS rebinding), все вызовы API требуют случайный токен.
- Ключ API никогда не отправляется в браузер.
- Экспорт файлов ограничен папкой результатов; содержимое вложений трактуется моделью как данные, не как команды.

