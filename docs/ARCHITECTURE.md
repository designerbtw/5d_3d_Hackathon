# Архитектура

## Потоки

| Поток | Что делает |
|---|---|
| Главный Qt-поток слайсера | Все операции с настройками, сценой и слайсингом |
| Потоки HTTP-сервера | Запросы браузера, SSE, MCP |
| Поток агента | Цикл «LLM → инструменты → LLM» для одного запроса |

Инструменты вызываются из потока агента или сервера, но выполняются через `run_on_main`: функция ставится в очередь `callLater` главного потока, вызывающий поток ждёт результат с таймаутом. Так слайсер не падает, а агент получает результат синхронно.

## Модули `AIAssistant/agent`

| Файл | Роль |
|---|---|
| `config.py` | Настройки; ключ из окружения или настроек приложения |
| `llm.py` | Клиент Chat Completions (urllib), повторы при 429/5xx |
| `agent.py` | Цикл агента: лимит шагов, кэш дублей, принудительный финал, страховка экспорта |
| `registry.py` | Единый реестр инструментов: валидация аргументов, ошибки возвращаются модели |
| `tools.py` | Определения инструментов и их обработчики |
| `mcp.py` | MCP поверх JSON-RPC 2.0 (`initialize`, `tools/list`, `tools/call`, `ping`) |
| `knowledge.py` | Рецепты материалов, белый список настроек и их проверка |
| `geometry.py` | STL, габариты, варианты ориентации и их метрики |
| `slicer_real.py` / `slicer_fake.py` | Одинаковый интерфейс: настоящий слайсер и заглушка для разработки |
| `server.py`, `events.py` | HTTP, SSE, токен, шина событий |
| `bootstrap.py` | Сборка компонентов, выбор адаптера слайсера |

## Решения и причины

- **SSE вместо WebSocket.** В стандартной библиотеке Python нет WebSocket, а `QWebSocketServer` живёт в главном потоке. SSE работает на обычном `HTTPServer` и сам переподключается.
- **Один реестр для агента и MCP.** Агент вызывает инструменты напрямую, MCP-эндпоинт даёт тот же набор снаружи; лишней сетевой петли внутри процесса нет.
- **Код считает, модель выбирает.** Проверка выданной модели (`qwen3.8-flash`) показала, что вызов инструментов и изображения работают, но свободный цикл многословен и иногда не доходит до экспорта. Поэтому добавлены: объединённый `get_state`, кэш повторных вызовов, лимит шагов с принудительным финальным ответом (`tool_choice: none` на последних двух шагах) и автоэкспорт.
- **Ориентация считается кодом.** Для каждого из 6+ вариантов (оси и самые большие плоские грани) считаются высота, площадь контакта, площадь свесов и оценка объёма поддержек. Модель выбирает вариант и объясняет компромисс, учитывая нагрузку: слои слабее вдоль оси, по которой они укладываются (`layers_stack_along`).
- **Значения не изобретаются.** `null` в рецепте означает «не задано»; система требует оставить профиль или спросить пользователя.

## Что ещё нужно сделать с реальным слайсером

1. Найти ключ режима classic / cylindrical / cylindrical_full в определении Hybrid 530 V5.2.4 и задать `PRINT_MODE_SETTING`.
2. Реализовать поворот (`RotateOperation`) с учётом оси Y вверх в сцене Cura.
3. Слайсинг: `forceSlice()` и ожидание сигнала завершения, чтение `PrintInformation`.
4. Экспорт G-code и 3MF через плагины-писатели.
5. Расширить белый список ключами Stereotech и свериться с экспертом по рецептам.
